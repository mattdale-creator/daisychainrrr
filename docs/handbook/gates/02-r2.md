# Gate — Cloudflare R2 enable

**Updated:** 2026-08-08  
**Status:** BLOCKED API error **10042** until dashboard enable  
**Purpose:** Object storage for large public artefacts (weights, shards, datasets) without pretending multi-TB delivery exists before storage exists.

## Why R2
- Public release distribution at scale
- ttlink shard hosting beyond repo git limits
- Separation of huge binaries from git history

## Human procedure
1. Cloudflare dashboard → account → **R2**  
2. Enable R2 / accept terms if prompted (clears 10042-class API blocks)  
3. Create bucket e.g. `ttllm-public-releases` (public read policy deliberate and documented)  
4. Create API token with R2 read/write as needed — store only in `ops/secrets.local.env`  
5. Document bucket name + public URL pattern in `continuity/ASSET_INVENTORY.md`  
6. Update `ops/HUMAN_GATES.md`

## After enable — engineering follow-ups
- Upload policy: only free-core artefacts; no tenant data
- Manifest entries include object hashes (SHA-256) matching free_core seals
- Lifecycle / versioning notes for Domain 3 withdrawals
- Never commit R2 secret keys
